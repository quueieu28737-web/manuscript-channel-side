\begin{abstract}
We propose a reporting framework for deciding which defense evidence can be reused when an LLM or agent deployment changes. It links source-versioned protection, function and cost measurements to the receiving view, affected execution state, and attacker and workload, yielding a scope-permitted comparison, an incompatible binding or a specific unresolved measurement.

Two bounded cases illustrate those decisions. In E4's post hoc synthetic TLS replay, a fixed logistic attacker trained on clean outputs scores balanced accuracy/AUROC 0.500/0.678 on one Qwen~8B four-chunk condition; when trained on defended outputs, it scores 0.732/0.773 on the same 500 topic-held-out outputs. In a separate retail-sandbox convenience sample of 98 tasks (187 three-arm groups), state-changing write cover has task-weighted success 46.9 percentage points below baseline (95\% task-bootstrap interval $[-56.8,-36.9]$). In E4, batched response application TLS bytes are 0.381 times the raw value, excluding requests and handshakes. E4 illustrates attacker fitting; R44 makes the state and utility of an executed action visible.

This is a methodological position paper: the reporting card is a proposal grounded in existing evaluation principles. Its usefulness and reliability remain to be evaluated. The cases are exploratory illustrations, and neither establishes a general defense effect or deployment-wide outcome.
\end{abstract}
