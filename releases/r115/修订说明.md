# R115 修订说明（回应 R114 的五项审稿意见和一处推理错误）

本版没有新的模型请求、抓包或实验，所有数字都来自已有的汇总结果。

| 意见 | 判断 | 修改 | 位置 |
|---|---|---|---|
| 突出核心亮点 | 同意 | 摘要、引言和结论都以“controller 诱饵缺少模型等待，这一差异能在真实 TLS 记录上被利用”开头；history 组写明“三/四项比较在 Holm 校正后仍有增益”；贡献 (1) 改为 dispatcher 泄露 | 摘要、§1、§11 |
| 1. 必要性论证过宽 | 成立 | 新增对 TLS 1.3 填充（§5.4）和 HTTP/2 帧填充与 PING（§6.1、§6.7）的分析。这些机制由服务端协议栈丢弃，能塑形请求侧，但无法让服务产生响应（PING 只换回立即返回的 8 字节 ACK）。结论收窄为：只有当隐私目标包括“发生了哪些请求–响应交换、响应大小和服务耗时”时，cover 才必须到达应用层；到达应用层不等于必须执行写操作，只读或 no-op 调用也能产生真实响应。表 3 改为“各种终止机制对最后一跳观察者还暴露什么” | §3，表 3 |
| 2. “达到 floor”易误读 | 成立 | 小节标题改为 “consistent with the floor”。正文写明：交换性只是假设，更强的角色识别攻击可能超过该参照，结果不能说明 shadow 已达到隐私极限。摘要改为“consistent with a 7/12 plausible-deniability reference” | 摘要、§1、§7.3、§8 |
| 3. Shadow 收益来源未分开 | 成立 | 新增 “What the shadow changes” 一段，说明 shadow 同时改变了三件事：cover 调用数（8.14/10.46，而 controller cover 是 5.6/6.8）、调用组成、模型 token（2.01×/1.99×）。明确不把收益归因于“由规划器生成诱饵”。待补测量中加入“controller 回放已记录的 shadow 链”作为分离实验 | §7.3、§8 |
| 4. 第三方服务能力与实验不匹配 | 成立，且揭示了实验前提 | 新增 service contract 段和表 5。实验依赖服务端的响应填充、服务端响应保持（代码中的 `HoldPaddedTool`）和隔离克隆，因此对应的是“合作型提供方”。明确写出：合作型提供方本身也能在应用层丢弃 cover 并返回填充后的延迟响应（即 proxy discard），而 dispatcher 结论同样适用，因为它关乎 cover 何时发出，与服务如何处理无关。非合作提供方的情形（响应未填充、无保持、作用于真实状态）未测量，已列入局限和待补测量 | §4、表 5、§8 |
| 5. 工件声明与实际不符 | 成立 | Availability 改为如实列出：公开部分（论文与 LaTeX、live 采集与分析代码、fixture 生成器、timing pools、冻结计划与哈希、record-only 代码、全部汇总结果、floor 脚本、44-setting 抽取、盲审编码表与裁决记录）和本地保留部分（逐例记录、逐调用时间戳与预测、抓包、TLS 密钥），并说明可复核到哪一步、哪些检查（如精确角色检验）无法复核 | §10 |
| §7.5 推理错误 | 成立，是我在 R114 中写错的 | 改为“当前样本不足以判定”。补充计算：若真实准确率等于 58.3%，约需 3,400 个测试样本，95% 区间上界才会低于 60%；若采用 distinct 标签采样（下限 50%），在现有 120 个样本下攻击处于下限时就能通过 | §7.5 |
