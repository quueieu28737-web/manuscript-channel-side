# R38：S&P 2027 投稿匿名、伦理与开放材料核查

核查日期：2026-10-27。本文是作者侧提交准备记录，不是会务方的合规认证。政策依据：[S&P 2027 CFP](https://www.ieee-security.org/TC/SP2027/cfpapers.html) 与 [Artifact Evaluation 征集](https://sp2027.ieee-security.org/cfartifacts.html)。具体投稿周期、作者和服务授权仍须由作者核实。

## 论文与 artifact 的匿名性

- 主稿和补充材料均使用空作者字段；对 PDF 文本、元数据和链接以及论文源文件包扫描仓库账号和本机用户路径。自动扫描只能覆盖预设模式，不能证明不存在其他能够识别作者的线索。
- 投稿时如引用作者自己的工作，应以第三人称正常引用；仅在第三人称确实不可行时才考虑隐藏引用。用户已确认投稿作者与 [2]、[7]、[40] 及其他被引论文没有作者重叠；作者名单未在仓库中核对，作者仍应进行最终身份关联审查。
- 论文源码包只包含主稿、补充材料和编译所需源文件，不是完整实验复现包。尚无证据证明完整实验包已完成匿名清理，也未确认可供审稿人访问的匿名 artifact 链接。不要将带账号信息的开发仓库作为匿名链接。
- 对准备发布的完整 artifact 逐项检查历史提交、用户名、路径、网络端点、密钥、日志、文件元数据、链接及 benchmark 数据发布权限，并提供匿名固定快照。CFP 要求审稿 artifact 在论文截止后不能更新；先确认是否已有正式提交或冻结链接，切勿覆盖已有审稿快照。

## 页数与投稿材料

- CFP 对正文规定至多 13 页，正文之后的文本和图表须明确标为附录；提交总数为 18 页，SoK 的参考文献页不计入。最终是否合规以最终提交 PDF 和会议解释为准，混有参考文献和附录内容的页面保守计入。额外的补充材料不能默认不受投稿页数限制；该 84 页材料作为独立研究资料，审稿系统是否接受以及如何提交应向会务确认。
- 投稿时须使用 IEEEtran 1.8b 的 `conference,compsoc` 模板和美式 letter 页面，不能通过修改边距、字体或行距规避限制。
- CFP 强烈鼓励匿名 artifact，并未规定一个名为 Open Science 的强制附录。录用后的 artifact evaluation 是独立流程；申请 Available badge 须按其规则提供永久公开、具有 DOI 的归档，普通 GitHub 分支本身不能替代此要求。

## 伦理、服务授权和数据范围

- 论文当前讨论的利益相关方包括租户、工具提供方以及可能受到意图推断或状态变化影响的用户。对攻击方法的可复用性应同时说明滥用风险与评估防御的收益；生产系统或漏洞披露若涉及真实第三方，应按 CFP 另行披露实际经过和权限。
- 基准任务、模拟用户、克隆状态与受控传输构成案例设置，但模型 API 可能由外部提供。研究记录尚未证明各服务方授权、具体 API 条款与数据发布许可；论文不能声称这些事项已核准。发布前核查服务方、数据持有人和适用许可，敏感信息、密钥、私有端点与未经许可的内容不纳入公开包。
- 预期可审计材料包括来源定位符、派生审计标签、协议、汇总结果和复算脚本；原始模型交互、数据集副本及第三方论文能否分享，应逐项核查权利和隐私。论文源码包本身未包含实验数据。
- 作者需在 HotCRP 完成 **Ethics Considerations** 和 **Generative AI usage considerations** 两个字段。PDF 中 §8.2 不能替代提交系统字段。说明 AI 作为研究对象，以及用于候选提取、源码实现、来源对账和文字修订；由作者负责确认输出及适用条款，并解释实验量与资源使用。不得填入未经证实的 IRB、授权或披露事实。
- CFP 要求所有作者在摘要提交时提供与 HotCRP 姓名及邮箱一致的 ORCID，并完整申报利益冲突。是否适用人类受试者审查、是否存在需要通知的真实部署漏洞及披露时间，须基于实际研究活动确认。

## 交付后仍待作者完成

1. 核对作者名单与所有自引、作者单位、致谢、元数据及外链，进行人工匿名审阅。
2. 核实模型服务授权、接口使用条款、数据集许可、隐私及可能的漏洞披露；无需把密钥写入投稿材料。
3. 准备并验证完整匿名 artifact 快照，确认截止日期后保持冻结。
4. 在 HotCRP 填写伦理、生成式 AI、作者 ORCID 和利益冲突字段；如存在第三方系统交互，按实际事实披露授权和风险控制。
