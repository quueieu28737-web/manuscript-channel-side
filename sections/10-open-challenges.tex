\subsection{Deployment paths and reporting obligations}\label{sec:deployment}
Table~\ref{tab:r19-decisions} specifies the missing measurement for each changed boundary. A passive observer may be an access-network operator, VPC monitor or inter-organization relay. Remote paths expose destinations even with Encrypted ClientHello \cite{rfc9849}; our measurements use one ingress endpoint. Host instrumentation and downstream commit logs require different protection.

Shadow state can use authorized reads/verified no-ops, provider isolation (Kubernetes dry-run, Stripe sandboxes, transactional rollback), or a trusted gateway routing marked writes to an isolated executor \cite{kubernetesdryrun,stripesandboxes,postgresrollback}. Idempotence alone is insufficient, and sequence changes can survive rollback \cite{postgressequences}. We measure the gateway path; provider integrations remain designs. The gateway can identify cover and is trusted. Ingress shaping competes with transport controls; restricted dispatch protection additionally requires hidden markers/routing. Quotas, backpressure and separate credentials must prevent overload and live side effects. The supplement details these deployment contracts.

\subsection{Ethics and artifact scope}\label{sec:ethics}
Executions use cloned public benchmark databases and loopback sockets; model requests contain public tasks and simulated interactions. No production account is modified or third-party service probed for a vulnerability. Stakeholders include paying tenants, shared-capacity providers and people affected by state changes. Other-account cancellation is a simulator control. Released inference code can support surveillance; examples use public/synthetic identities and controlled endpoints. Bot-detection evasion has a different authorization boundary \cite{zhu2026turing,jeong2026wra}.

AI tools assisted candidate-field extraction, implementation, source reconciliation and prose revision; the authors verified the original source-linked corpus and retain responsibility for the revised synthesis. The artifact archives source locators, coding decisions, observations, calibration and executable checks.

\subsection{Threats to validity and scope of evidence}\label{sec:validity}
\paragraph{Statistical scope}
The BA/AUROC screen is an engineering threshold, not a security definition. No defended configuration meets it for both targets; paired reductions establish improvements against specified fitted suites only. Nominal 95\% intervals reselect the suite maximum; they omit retraining uncertainty and multiplicity adjustment. The frozen split has 5/7 positive customers; the full cohort has 14/18. Repeats add execution coverage. Reference calibration uses the known population. Real-agent calibration precedes held-out collection, but developers knew the task set; cross-fit, timing and transfer extensions are exploratory.

\paragraph{Targets and deployment utility}
Operation targets are coupled to intended actions; localization identifies their metadata signature. The same-operation attribute diagnostic is inconclusive (Appendix~\ref{app:experiments}). Original agent reward, defended logical conformance and live prefix-shadow utility are distinct outcomes. Full framing/flush utility remains unmeasured. Loopback RPC timing excludes LLM generation, and WAN effects are emulated in the relay rather than measured on wide-area paths. WF adapters support matched metadata comparisons; original-protocol equivalence and equal-utility deployment comparisons remain open.

\paragraph{External validity}
The four mutable model aliases operate in one retail environment with separate user-simulator contexts. Luna has 29 training tasks; MiniMax and GLM each have 69. Transfer matrices and live planning reuse known customers. Fresh customers, fixed weights, verified cross-provider identities, new environments and provider-backend measurements define the next validation axes.
